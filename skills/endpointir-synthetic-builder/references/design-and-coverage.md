# 自主设计与覆盖

## 从目标构造链

先构造虚拟业务上下文，例如日志处理主机、文件交换节点、批处理工作机或开发辅助机。指定单一目标、已获授权的起点、权限、主机角色和调查触发点。未实现入口时明确 assumed-breach，不虚构漏洞、入侵组织、日期、受害者或 CVE。

以输入输出推导链：上一步实际生成的文件、配置或服务状态由下一步消费。例如受控获取载荷 → 启动本地程序 → 识别业务目录 → 选择目标文件 → 暂存 → 归档 → 实际传输 → 接收端保存。发现步骤应影响后续选择，不能只是依次执行若干互不相关的命令。

同一场景可含分支、汇合或有限重试，但依赖图为 DAG。因果依赖写 designed_dependency，单纯调度先后写 designed_order。ATT&CK tactic 不规定线性顺序。

默认尝试 10–16 个实质操作、5 类以上 tactic。不要把 mkdir、写测试数据等环境准备算攻击节点，不把一次归档拆成几个同义节点凑数。每个节点能说明行为目的、技术映射、输入输出、证据与后续作用；无法说明的节点优先删除。生成前可删改设计，执行失败后不能悄悄删检查点减少评分分母。

## 可组合候选

以下是内置知识的候选提示，不是从在线元数据核实的清单。优先选择自己有把握且目标 Linux 支持的映射；不确定子技术时保留父技术或留空，说明不确定性。技术名或 tactic 归属不确定时不要造出版本号或以网络查询替代本任务的知识生成方式。

| 目的 | 候选 ATT&CK 映射 | 可调查的合成实现与必要边界 |
|---|---|---|
| 执行 | T1059.004 Unix Shell | 调用自带的良性脚本；进程/服务记录或真实应用副作用支持执行事实 |
| 获取附件 | T1105 Ingress Tool Transfer | 从本地隔离 HTTP 服务获取自带文件；同时保留请求、接收字节及后续使用关系 |
| 解码 | T1140 Deobfuscate/Decode Files or Information | 解码合成配置并实际消费；解码结果与输入关联，不把文件改名算作解码 |
| 系统发现 | T1082 System Information Discovery | 查询目标系统属性，并被后续任务选择使用；不能把预填文本当查询证据 |
| 用户发现 | T1033 System Owner/User Discovery | 读取实验用户上下文；普通查询不等于取得凭据 |
| 文件发现 | T1083 File and Directory Discovery | 枚举合成目录，候选清单成为后续收集输入 |
| 进程发现 | T1057 Process Discovery | 发现预置良性服务进程，需保存实际可归因的采集证据 |
| 网络配置发现 | T1016 System Network Configuration Discovery | 检查实验接口/配置；不向外部地址扫描 |
| 定时执行 | T1053.003 Cron | 在具备 cron 的隔离环境中配置专属任务并验证真正触发；不能以一次 sleep 替代 cron |
| 服务执行/持续运行 | T1543.002 Systemd Service | 专属用户级服务，平台必须具备可用 systemd；服务触发和效果应可验证 |
| 本地收集 | T1005 Data from Local System | 仅读取预置合成业务文件，记录可关联的实际选择和复制 |
| 暂存 | T1074.001 Local Data Staging | 真实复制到暂存区；逐字节比对与上下游关系 |
| 归档 | T1560.002 Archive via Library | 用标准库实际生成归档，检查成员与内容 |
| 受控传输 | T1048.003 Exfiltration Over Unencrypted Non-C2 Protocol | 隔离 HTTP 上传与真实接收文件；loopback 只覆盖本机传输机制，不宣称跨主机外传 |
| 受限应用协议交互 | T1071.001 Web Protocols，候选 | 固定次数、固定消息的隔离服务交互；普通 HTTP 下载不自动证明 C2，任务/回执语义不足时不计此技术 |
| 文件删除 | T1070.004 File Deletion | 仅删除本场景的可丢弃中间文件；必须有事前状态与实际删除的独立遥测，否则仅作为清理，不出删除事实题 |

同一行为可能兼具多个 tactic，但只有在实际上下文支持时才能标注。使用 Python 实现全部动作不表示全部节点都覆盖 Python 命令解释技术；普通读文件也不能机械叠加多个收集技术。

## 场景组的互补性

用户要求多个场景时，组合不同机制、证据源和拓扑，而不是更换文件名：

- 批处理主机：获取 → 解码配置 → shell 执行 → 定向发现 → 收集/归档 → 受控上传。
- 调度主机：准备专属任务 → 真实定时触发 → 进程与环境发现 → 业务产物生成；需要 cron 或 systemd。
- 文件服务：多来源业务目录 → 筛选 → 暂存汇合 → 归档 → 接收核验，加入相近但无关的正常作业。
- 生命周期调查：生成临时产物 → 后续消费 → 有审计的定向删除，调查遗留元数据与跨日志关系。

仅当用户已指定隔离多主机环境时才设计角色间传输或测试账户访问；预置授权登录不自动等于凭据窃取或权限提升。不得为了覆盖初始访问、提权、凭据访问、横移或影响阶段，自动加入真实漏洞利用、真实秘密读取、通用远程命令执行、规避监控或破坏性操作。缺口留在 README 中，使用受限测试语义时清楚界定可回答的事实。

## 证据与难度

每个核心步骤至少一项可恢复证据；每条关键因果边至少能通过共享实体、请求关联或真实审计建立联系。纯时间相邻不能证明父子进程、文件来源或数据流。查询命令 stdout 若只存在控制端 transcript，不能作为靶机可调查事实；启用实际遥测或调整问题边界。

加入少量同类正常活动（正常归档、未被选中的文件、正常服务请求），让 Agent 区分目标链，不能通过目录名 ATTACK/ANSWER 或自造“攻击成功”日志透露答案。所有合成文件使用中性名称，记录固定 seed 和配置便于重建，执行时间、PID、实际端口及动态实体由 verifier 观测。

难度来自证据分散、合理噪声、跨文件关联和提示减少，不来自缺失关键证据。L1–L3 使用同一现场与同一 QA；自由报告中的原子事实由 LLM 裁判语义判定，再计算 Precision/Recall/F1。不得把场景验证器通过率当作 Agent 评测结果。后续效率评测在控制端记录调查耗时、工具调用次数与 token 用量，各 Agent 使用相同环境、问题和预算；生成脚本的运行耗时不作为调查效率。

## 覆盖统计口径

在 README 给出设计节点数、可执行节点数、不同父技术族/子技术数、tactic 分布、已实测证据项数和主要缺口即可，不另建独立覆盖文件。

- 设计涉及：图中候选技术；未知、omitted 项明确分开。
- 实现覆盖：implementation 的实际机制及其映射，只是代码已生成。
- 实测覆盖：实际执行且相关证据检查通过的节点。完整、部分/等价和省略分别统计；候选映射依然未经官方核对。
- 镜像可评测覆盖：恢复后仍可验证的事实；仅运行时存在而未留存的事件不能计入。

按 ID 去重，多次重复不增加覆盖。父技术族数与子技术数不相加，跨场景汇报并集。没有一个已固定且核对过的 ATT&CK 总表作分母时，只报告计数与列表，不给“覆盖整个 ATT&CK 的百分比”。
