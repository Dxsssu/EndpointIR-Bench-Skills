# 自包含 Linux 执行与独立证据

## 运行包

`run.sh` 以自身位置定位 `artifacts/`，不依赖调用者 cwd、Codex、在线模型、报告、外部数据库或其他 Skill。优先 Bash/Python 标准库。全部测试输入与服务由自带程序生成，不下载未知载荷。操作只限专用工作区、专属测试账户和明确的实验资源。

使用 `set -Eeuo pipefail`，路径变量加引号。模式如下：

- plan：跨平台打印动作、依赖与修改范围，无探测、写文件或执行副作用。
- check：只读检查 Linux、Python、工具/服务、权限、端口、工作区与遥测能力。缺少条件给出原因，不自动安装软件或更改系统服务。
- execute：先 check，再按图的显式依赖调用代码；不 eval 图或字符串，不重复覆盖旧现场。所有进程、请求、循环、等待有上限。
- verify：调用 `artifacts/verify.py`，JSON 到 stdout，诊断到 stderr；缺失必要证据返回非零。
- cleanup：显式清理本次拥有的精确路径、任务与 PID，容忍部分失败；不删除共享日志、用户数据或其他任务。

拒绝根目录、用户主目录本身、非本场景已有目录及符号链接逃逸。所有权 marker 仅用于限定清理范围，不能用作事实恢复证据。临时服务启动成功才继续，退出只停止自己创建的进程，执行失败保留现场用于诊断。

网络默认仅 loopback，或用户已指定的隔离实验网络；固定服务行为、有限消息与合成数据，不创建通用远程命令通道。不给宿主机装持久化，不关闭监控，不访问真实凭据或外网目标。专属定时任务和服务只能在实验靶机存在，并提供精确清理。

## 行为必须可观测

脚本应真实创建进程、文件、归档、任务或网络请求，日志来自实际处理行为。不能写“攻击成功”“已提权”等说明冒充系统审计。验证器不得导入运行器或读取图、QA、运行成功标志作为真值；可内嵌独立预期条件，但 answer 要由实际观测构造。

每步设计时列出证据条件。例如文件存在只支持存在事实，不能自动证明下载来源或执行过；归档文件不能证明外传；任务配置不能证明已触发；删除后的文件缺失不能单独证明删除事件。验证关键关系需要实际请求日志、服务日志、audit 等遥测及独立副作用。

系统不具备所需遥测时，在生成阶段缩小事实范围或选另一种有证据的机制。执行后失败则保留失败状态，不能直接删除问题、编造日志或把 simulate 输出称为系统记录。

受控替代应声明 preserved_semantics 与 changed_semantics。例如本机上传保存字节可证明传输成功，不能证明真实攻击者收到数据；假凭据读取不能证明获取真实账户权限；预授权限不算提权。ATT&CK 知识有把握也不能代替运行验证。

## 镜像与评估端分离

QA、图、验证器及验证报告留在评估端。靶机只传运行所需附件，验证器通过只读远程调用/stdin 或临时复制执行，保存镜像前移除构建/评分材料。不要清空自然业务日志或移除作为攻击链实体的行为产物。

验证报告保存到评估端 `artifacts/results/`；finalize 填入标准答案。使用实际虚拟化平台保存环境，再从镜像恢复并以 restored_image scope 重验。镜像未生成就明确待生成，不用日志包冒充镜像。

OCI/Docker 镜像适合持久文件与应用日志，不保存原进程和内存；systemd/cron 的启停条件要明确验证，不能认为容器 commit 后所有机制都仍可调查。全 VM 与容器分别标明，记录架构及恢复命令。打包与校验通过只证明格式，实际恢复成功才证明交付形态可用。
