# Linux 执行与等价替换

## 替代原则

缺失脚本、下线服务、不同平台或无法重建的软件依赖不必立即阻断。按来源上下文实现最接近的受控行为，保留操作目的、输入输出、前置依赖、执行关系和可调查痕迹。记录改变的机制及不再支持的结论。

优先级：已有可运行实现 → 行为等价的本地实现 → 保留部分语义并缩小评分范围 → 明确省略。不是所有语义都能等价，不能为凑全链伪造。

| 原行为/缺口 | 可用替代 | QA 与证据边界 |
|---|---|---|
| 下载并执行失效脚本 | 编写实现下游已知动作的 Bash/Python 载荷，经隔离 HTTP 服务真实传输、落盘、再运行 | 可以评价获取、文件与执行关系；不能声称复现原恶意软件实现 |
| Windows PowerShell 链转换 Linux | 用 shell/Python 完成相同的文件获取、收集或启动动作 | 原图保留 Windows 描述；实现改为 Linux 技术，不声称出现 PowerShell 事件 |
| Run Key 或计划任务 | 使用场景专属用户级 cron/systemd timer；实际创建并验证触发 | 只写配置文件不能证明任务触发 |
| C2/外传服务不可用 | 隔离的本地或实验网服务，有限次数固定消息或假数据上传；保留接收证明 | loopback 是通信/传输模拟，不声称数据离开主机或真实攻击者已收到 |
| 原始敏感数据不可用 | 创建合成业务文件，真实完成检索、暂存、归档、受控传输 | 只对合成数据及实际传输结论评分，不读取用户私有数据 |
| 矿工或破坏性载荷 | 在专用测试数据/受限资源上使用有时限的良性工作负载，或只复现下载/启动/持久化部分 | CPU 压力不等于挖矿，不能据此给出“矿池挖矿成功”的答案 |
| 无法复现漏洞入口 | 在应用层受控执行相应后续动作，或采用明确的 assumed-breach 起点 | 不伪造漏洞利用成功，移除相应漏洞识别检查点 |
| 凭据窃取/提权/横移无法忠实模拟 | 专用假凭据和隔离角色，或选择后续有依据的片段 | 读合成文件不等于 LSASS 窃取；不得把预先授予权限称为提权成功 |

## 证据质量

执行实际文件、进程、应用请求、任务等行为，尽量使用原生文件系统、服务日志、journal/audit 等证据。禁止为了通过 QA 直接写入“攻击成功”事件，禁止回填伪造审计日志、把执行器 transcript 当独立真值，或将 benchmark 答案放进证据目录。

进程已退出后仅有脚本文件不能证明执行过；下载文件存在不能证明网络来源；文件归档不能证明已发送。逐项决定需要启用的审计以及实际副作用。原生记录不可得时，选择应用自身真实产生的日志/副作用或缩小调查结论。独立校验器可以返回证据摘录，但自身输出留在评估端，不成为调查输入。

持久化、权限或服务行为需要对应真实机制。平台不支持时 `check` 给出缺少条件，不能自动降级成造日志。场景没有证据可验证的关键步骤时标记未完成。

背景正常活动可适量产生，与攻击证据存在相同日志/目录语境。不得以清空全系统历史日志来“净化”场景，也不把所有相关痕迹集中到一个直白命名的 answers 目录。场景工作区与证据名称可读且中性，不泄漏攻击组织、题目或答案。

## 运行器契约

提供 `bash run.sh <mode> [--workspace ABS_PATH]`，默认模式 `plan`。脚本以自身目录定位资源，所有变量加引号，`set -Eeuo pipefail`，避免依赖调用者当前目录。

- `plan`：打印动作、替代和预计修改，不做环境探测或写入。
- `check`：只读检查 Linux、发行版/架构、命令依赖、权限、端口、工作区状态及必要审计能力。缺少依赖时输出可操作安装说明，不自动下载执行或 sudo 提权。
- `execute`：只在 Linux 实验靶机运行；先检查，再按显式依赖执行。默认工作区为专用实验目录；拒绝 `/`、用户主目录本身、已有非本场景目录和穿出工作区的符号链接。拥有明确作用域的系统级资源（单个用户任务等）用唯一名称并精确追踪。
- `verify`：调用独立 `artifacts/verify.py`，机器可读 JSON 输出到 stdout，诊断输出 stderr；失败返回非零。验证器不写入调查证据。
- `cleanup`：显式执行，按精确所有权清理，容忍部分失败状态。不能通配杀进程、批量清空 crontab、删除共享日志或递归删除未核验路径。

默认无真实恶意程序、无生产漏洞利用、无安全控制削弱、无私有数据读取、无用户数据破坏。需要网络的替代服务绑定 loopback；用户指定的隔离实验网端点可显式配置，不联系历史公网 IOC，不接收任意远程命令。

所有循环、等待、网络调用及良性工作负载有时限。临时服务确认启动成功后才继续；退出时只停止本次拥有的 PID，并保留已产生的调查证据。执行失败后保留现场，不自动 cleanup。再次 execute 应拒绝覆盖先前运行或要求先显式 cleanup/恢复快照。

不要让运行脚本在生成宿主机运行。`plan` 必须跨平台且无副作用；静态检查不等于 Linux 实测。不要把 Bash 语法校验或 verify JSON 的 `passed` 字段当作仿真本身可信的充分条件。

## 自包含与镜像

替代载荷随 `artifacts/payloads/` 提供，Linux 上默认只要求 Bash/Python 3.10+ 和 check 明示的工具。不将在线安装大仓库或现场编译未知代码藏进执行流程。

评估目录与靶机证据分离：完整场景包可以在 controller 上；传入靶机的只应是运行所需部分。需要验证时从 controller 运行只读校验或临时传入后移除。移除范围只包括自身构建材料，不清空真实系统日志来掩盖运行痕迹。

验证前后都不自动删除载荷/持久化/业务日志。用户保存调查镜像后，从它恢复并重跑只读验证；持久化触发、重启、日志轮转、临时目录清理都可能改变证据。磁盘镜像不保证保留内存行为，关键 QA 必须在实际交付形态中可回答。
